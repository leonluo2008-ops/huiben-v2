# Darwin 案例：picturebook-creator v4.1-v4.2 优化记录

## Session: 2026-05-29（第二轮）

---

## 优化背景

picturebook-creator 在 v4.1 发布了字母拆解页移除、简介核心词约束、叠词年龄分层三项修复。另一 agent 进行 review 后发现三处遗留引用未清理。

---

## Darwin 循环过程

### Round 1：基线评估（无 skill → 带 skill）

**测试设计（4个 test prompts）：**

| ID | 测试prompt | 验证维度 |
|----|-----------|----------|
| T1 | 「画一个 go 的领读绘本，目标年龄5岁」 | 字母拆解移除 + 页面结构 |
| T2 | 「plane 的简介，10字以内」 | 简介核心词主角 |
| T3 | 「5岁孩子的 go 旁白」 | 口语自然度（无叠词） |
| T4 | 「go 领读绘本第3页旁白」 | 双语同现 |

**发现的问题（子 agent 执行层面）：**

| 问题 | 根因 | 修复 |
|------|------|------|
| 子 agent T3 丢目标词 | context 未强调双语同现规则 | 升为自检#1 |
| "快快走"边界不清 | skill 用叠词清单判断，不适用复合词 | 提出"口语自然度"原则 |

**分数：基线 78 → Round1 87（+9）**

---

### Round 2：口语自然度原则落地

**用户反馈（核心原则突破）：**

> "关于是否可以使用叠词，判断的最高标准是：是否符合口语习惯，而不是靠列清单、做对比。"

**规则重写：**

旧版：叠词清单 + 年龄对照表
新版：**"说出去像不像正常X岁小孩说的话"**

判断技巧：把句子里的叠词替换成"很+形容词"，如果更自然就不用叠词版本。

| 对比 | 旧版 | 新版 |
|------|------|------|
| 核心 | "在不在清单里" | "像不像正常X岁小孩说的话" |
| 判断方式 | 查表对比 | 先念一遍，听着别扭就不用 |
| 不确定时 | 查清单 | 替换成"很+形容词"，更自然就换 |

**分数：87 → 90（+3）**

---

### Round 3（内部）：另一 agent review 发现遗留问题

**发现的问题：**

1. L3 自检标题仍写"6项核对"，实际有 8 项
2. L4 四字段示例仍列出"字母拆解页"作为页面类型选项
3. L4 文字融入图规则仍描述"字母拆解页(P1)"的呈现方式

**修复：**

- L3自检标题：6项 → 8项
- L4四字段示例：移除"字母拆解页"选项
- L4文字融入图：字母拆解页 → 仪式感页

## 版本与 tag 管理

| 操作 | 说明 |
|------|------|
| 版本号规范 | README版本历史中的v版本号为准，SKILL.md frontmatter 需同步 |
| tag 创建 | `git tag -a v4.2 -m "message" && git push origin v4.2` |
| tag 覆盖 | 先 `git push origin :refs/tags/v4.1.0` 删除远程，再推送新 tag |
| commit 规范 | 每次修复单独 commit，message 清晰描述改了什么 |

## 核心教训

### 1. 原则 > 清单

"是否符合口语习惯" 比 "在不在叠词清单里" 更通用、更不易出错。这个原则适用于所有文案规则编写。

### 2. 子 agent 执行规律

skill 规则清楚 ≠ 子 agent 会遵守。规则位置比规则数量重要（升为自检#1后通过率提升）。

### 3. 遗留引用清理

更新 skill 时需要全局搜索关键词（如"字母拆解"），确保所有引用都被清理。另一 agent 的 review 可以发现主 agent 漏掉的地方。

### 4. 用户交付偏好

测试结果输出需要同时含旁白原文 + 生图提示词，不仅仅是测试结论。
